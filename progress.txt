DEXTRA PROJECT PROGRESS
=======================
Last updated: 2026-10-07

Purpose
-------
This file is the running change log for the Dextra demo. Whenever future work
changes project files, dependencies, runtime setup, or verified behavior, update
this file in the same work session. Record the date, what changed, and relevant
validation results. Keep older entries; append a new dated entry rather than
replacing the history.

Project status
--------------
The demo-first rehab dashboard is implemented and was reported running under
Uvicorn. Device session ingestion, SQLite persistence, dashboard metrics, history,
achievements, and the exercise library are present. The implementation follows
the supplied Spec.md and intentionally prioritizes a working demo over completeness.

Changes completed to date
-------------------------
1. Reviewed Spec.md and established a demo-first implementation scope.
2. Created the FastAPI application and supporting packages:
   - app/main.py: app bootstrap, router registration, static files, database
     initialization, and exercise-library seeding.
   - app/database.py: SQLAlchemy engine, SQLite configuration, and session setup.
   - app/models.py: session and exercise persistence models.
   - app/schemas.py: request/response schemas, updated for Pydantic v2.
   - app/seed_exercises.py: starter exercise-library data.
   - app/services/metrics.py: dashboard metrics, including success rate, streak,
     and rolling seven-day trend; guarded division by zero.
   - app/services/achievements.py: demo achievement thresholds and badges.
   - app/routers/api.py: POST /api/ingest endpoint; demo patient is fixed to
     usr_9876 and the provided session timestamp is retained.
   - app/routers/dashboard.py: dashboard, history, achievements, and exercise
     library routes.
3. Added Jinja2 templates for the shared layout and the dashboard, session
   history, achievements, and exercise library. Added lightweight CSS and a
   Chart.js weekly trend visualization.
4. Added tests in tests/test_app.py for dashboard rendering, ingest behavior,
   and zero-division handling.
5. Added simulate_device.py at the project root. It supports --once to POST one
   realistic device session and --seed N to generate backdated demo sessions
   over N days using httpx.
6. Added DESIGN.md as the app design brief.
7. Fixed a dashboard template issue by passing the weekly total explicitly
   instead of summing a dictionary method in Jinja.
8. Fixed a Pydantic v2 configuration warning by using ConfigDict with
   from_attributes=True.
